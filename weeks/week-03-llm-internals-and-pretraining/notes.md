# Week 3 Notes — LLM Internals and Pre-training

Source: [Week 3 lecture slides](resources/Week%203.pdf) — Looking Inside LLMs, and Pre-Training at Scale: BERT, GPT, and Modern LLMs. Reference: *Hands-On Large Language Models* (Alammar & Grootendorst, 2024, O'Reilly).

## Key terms

- **Autoregressive model** — a model that consumes its own earlier predictions as input to make later predictions (each new token is appended to the prompt before the next forward pass).
- **Forward pass** — one full pass of input through the model (tokenizer → Transformer block stack → LM head) to produce output.
- **Tokenizer** — holds the vocabulary (token ID ↔ token table) that converts text to/from token IDs.
- **Token embedding** — the learned vector representation associated with each vocabulary token.
- **LM head (language modeling head)** — a neural network layer that converts the final hidden state into a probability distribution over the next token.
- **Decoding / sampling** — the strategy for picking the next token from that probability distribution (e.g. greedy decoding = always pick the highest-probability token; or sample randomly/with temperature).
- **Context length** — the maximum number of tokens a model can process at once.
- **KV cache (caching)** — storing the results of earlier token computations so they don't need to be recomputed at every new generation step.
- **Encoder** — reads input text and builds a representation of it (e.g. BERT).
- **Decoder** — generates text one token at a time (e.g. GPT).
- **Pre-training** — the initial, large-scale training phase where a model learns from raw data (from scratch or from initialized weights), before any task-specific fine-tuning.
- **Masked Language Modeling (MLM)** — pre-training objective where some tokens are hidden and the model must predict them from surrounding (bidirectional) context — used by BERT/RoBERTa.
- **Causal Language Modeling (CLM)** — pre-training objective where the model predicts the next token using only preceding tokens — used by GPT-2/3/4.
- **Span corruption** — pre-training objective where whole spans of consecutive tokens are removed and the model must reconstruct them — the main objective behind T5.

## Summary

### Looking inside an LLM

- **Input/output model:** an LLM is a software system that takes in text (a *prompt*) and generates text in response (the *generation*).
- **One token at a time:** the model does not produce the whole response in one shot — each token is generated by one forward pass through the model.
- **Autoregressive generation:** after each token is produced, it's appended to the end of the input prompt, and the (now longer) prompt is fed back in to generate the next token. This "consuming your own earlier predictions" pattern is what *autoregressive* means in ML.
- **Forward pass internals:** a prompt flows through a **tokenizer**, then a **stack of Transformer blocks**, then an **LM head**.
  - **Tokenizer & embeddings:** the tokenizer's vocabulary maps each token to a token ID; the model holds a learned vector (embedding) for every token ID in that vocabulary.
  - **LM head:** a simple neural network layer that outputs a probability distribution over every possible next token (e.g. "Dear" 40%, "Title" 13%, "To" 8%, "Hi" 2%, ...).
  - **Decoding/sampling:** the strategy that turns that probability distribution into an actual chosen token — greedy decoding always takes the highest-probability token; other strategies sample (possibly randomly) from the distribution.
- **Parallel tokens & context length:** each input token flows through its own computation path in parallel across the Transformer stack. **Context length** is the hard limit on how many tokens can be processed at once.
- **Caching (KV cache):** once a token's intermediate calculations are done, they can be cached and reused rather than recomputed on every subsequent generation step — this is what makes autoregressive generation computationally feasible.
- **Inside a Transformer block:** LLMs stack many Transformer blocks (6 in the original 2017 paper, 100+ in large modern LLMs); each block processes its input and passes the result to the next block. Within each block:
  - The **attention (self-attention) layer** incorporates relevant information from other tokens and positions — e.g. in *"The dog chased the squirrel because it..."*, attention is what lets the model work out whether "it" refers to the dog or the squirrel.
  - The **feed-forward layer** houses the majority of the model's processing capacity/parameters (this is the MLP(GELU) sub-layer from Week 2).
- **Encoder vs. decoder:** an **encoder** (e.g. BERT) reads input text and builds a representation of it; a **decoder** (e.g. GPT) generates text one token at a time, autoregressively.

### Pre-training at scale

- **What pre-training is:** the initial phase of building an LLM, where the model is trained from scratch (or from initialized weights) on large amounts of raw text, before any task-specific adaptation. Pipeline: **Pre-training → Adaptation/Fine-tuning → Application**.
- **What a model learns during pre-training:**
  1. **Vocabulary & token patterns** — e.g. "machine" commonly precedes "learning".
  2. **Syntax** — grammatical structure (e.g. "The students are working.").
  3. **Semantic relationships** — e.g. doctor↔hospital, teacher↔school, Paris↔France.
  4. **Long-range relationships** — e.g. resolving "he" to "John" in *"Sarah gave the book to John because he wanted to read it."*
- **Three pre-training objectives:**
  - **Masked Language Modeling (MLM)** — hide some tokens in a sentence; the model predicts them using surrounding (bidirectional) context. Core objective for bidirectional encoders like BERT and RoBERTa.
  - **Causal Language Modeling (CLM)** — predict the next token using only the tokens that came before it. Core objective for GPT-style decoder models (GPT-2/3/4).
  - **Span corruption / span masking** — remove a whole span of consecutive tokens (not just single tokens) and train the model to reconstruct the missing span. Main pre-training objective behind T5.
- **BERT vs. GPT vs. T5:**

  | | BERT | GPT | T5 |
  |---|---|---|---|
  | Architecture | Encoder only | Decoder only | Encoder–Decoder |
  | Pre-training | Masked LM + Next Sentence Prediction | Causal LM, left-to-right | Text-to-text, "fill-in-the-blank" |
  | Masking | Bidirectional (sees all tokens) | Causal / unidirectional | Input full, output causal |
  | Best for | Classification, NER, QA | Text generation, few-shot | Translation, summarization, multi-task |
  | SOTA example | BERT-large (340M) | GPT-3 (175B) | T5-11B |
  | Key paper | Devlin et al. 2018 | Radford et al. 2018 | Raffel et al. 2019 |

- **The modern LLM family:**

  | Model | Org | Params | Context | Architecture | Key strength |
  |---|---|---|---|---|---|
  | GPT-4 | OpenAI | ~1.8T (MoE, est.) | 128k | Decoder-only MoE | Multimodal, function calling, RLHF-aligned |
  | LLaMA-3 | Meta AI | 8B / 70B / 405B | 128k | Decoder-only (GQA + RoPE) | Open weights, best open-source baseline |
  | Mistral | Mistral AI | 7B / 8×7B MoE | 32k | Decoder, sliding-window attention + GQA | Very efficient, sliding window attention |
  | Gemma | Google | 2B / 7B / 27B | 8k | Decoder-only (multi-query) | Distilled from Gemini, strong reasoning |
  | Qwen | Alibaba | 0.5B – 72B | 32k | Decoder-only (RoPE + GQA) | Multilingual, code, math specialisation |

- **Parameter counts:** e.g. GPT-3's 175B parameters means ~175 billion learned numerical values, coming from the embedding layer, attention layers, feed-forward layers, and output layers. **More parameters ≠ automatically a better model** — capacity to learn complex patterns increases, but quality also depends on training data, architecture choices, tokenizer, and context length.
- **Why decoder-only dominates (2024 discussion):** GPT-4, LLaMA-3, and Mistral are all decoder-only rather than encoder-decoder (like T5), because decoder-only scales better — the KV cache enables efficient generation, there's no cross-attention overhead, and next-token prediction is simpler to train at scale.
  - *Is BERT dead?* No — it remains the best choice for classification and retrieval tasks where bidirectionality matters (NER, QA, semantic search), and encoder models are smaller and faster at inference.
  - *Model choice by task:* sentiment analysis → encoder-only (BERT-class); machine translation → encoder-decoder (T5/NLLB) or a large decoder-only model with prompting (GPT-4).

## Code / examples

- Autoregressive loop (conceptual): `prompt → model → next_token; prompt = prompt + next_token → model → next_token; ...`
- MLM example: `I am a [MASK] Assistant` → model predicts `Virtual`
- CLM example: given `I am a Virtual [MASK]`, predict the next token → `Assistant`
- Span corruption example (T5-style): `<id_0> brown fox <id_1> lazy dog` → model reconstructs the missing spans at `<id_0>` and `<id_1>`
- `tiny_transformer_llm.py` in this week's resources is the Lab sheet 3 starter: it loads the TinyStories dataset, tokenizes at the character level, builds a small causal Transformer (`nn.TransformerEncoderLayer` + causal mask — i.e. decoder-style/GPT-style CLM), trains it with cross-entropy loss, evaluates validation loss/perplexity, generates text from a prompt, and (optionally) serves it through a Gradio chat UI.
